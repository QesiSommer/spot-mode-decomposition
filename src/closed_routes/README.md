## 一、形态先验重搜索路线 —— 已证伪（2026-10-14）

**动机**：4 奇点出现"高相关但轮廓不像"（`C_s02 = 0.9163` 但中央暗区占比 34%，
实验仅 6%）。于是引入"形态守门员"（中央暗区差 / 轮廓起伏比 / 形状谱距离）
驱动 4/5/6/9/11 五图重搜索。

**结果：指标判 PASS 的解，视觉上反而更差**，经用户逐图视觉复核，
**全部不采纳**（含 `C_s02` 上升的 4/9 奇点）。主归档（v3）保持不变。

| 脚本 | 作用 |
|---|---|
| `morphology_metrics.py` | 形态指标计算（中央暗区 / 轮廓起伏比 / 形状谱距离） |
| `morph_search_lib.py` | 形态先验搜索库（全自由度渲染/精修，`render_dof`） |
| `stage13a_4sing_morph_search.py` | 4 奇点形态先验重搜索 |
| `stage13b_4sing_morph_dof.py` | 形态候选的完整自由度精修与判定 |
| `stage13c_4sing_morph_full.py` | 全空间形态普查（366,145 三模组合） |
| `stage13d_4sing_morph_delivery.py` | 4 奇点形态修复交付 |
| `stage14_morph_audit.py` | 八图形态审计（初版，朴素渲染管线） |
| `stage14b_morph_audit_v2.py` | 修正版形态审计（全自由度管线） |
| `stage15_morph_fleet.py` | 5/6/9/11 奇点形态先验重搜索（多阶漏斗） |

**失败机理（三条，值得记住）**：

1. **形态指标是"几何代理"，不是视觉相似度**——中央暗区占比只统计"暗像素比例"，
   不区分暗洞的**形状**；轮廓半径谱只看 `r(θ)` 的谐波强度，
   对**内部亮斑结构完全不敏感**。所以能找出"中央占比对、轮廓谱对，
   但内部亮斑乱掉"的解；
2. **搜索被形态约束过早剪枝**——形态普查把 366,145 个组合压到 0.17%~0.81% 的
   "通过"集合，而这些组合整体 `C_s02` 偏低（最高约 0.87），
   **高 `C_s02` 组合几乎全被形态门挡掉**，说明在该指标下"好看"与"高分"本就冲突；
3. **反证**：本轮结果反而说明 `C_s02` 是更可靠的视觉代理——
   它虽对某些低频形态差异不敏感，但**绝不会把"内部乱掉"的解评为高分**。

**保留的有价值副产物**：

- `morph_search_lib.py` 的 `render_dof` —— 全自由度渲染/精修库（可复用工具）；
- **管线一致性教训** —— 任何审计/评估都必须使用与交付一致的渲染管线。
  初版审计（仅 theta 的朴素渲染）误判 9 奇点为 FAIL、8 奇点1 为 PASS，
  改用完整管线后结论翻转。

完整记录：`reports/归档_八图分解/形态修复_2026-10-14/负结果记录_不采纳.md`

## 二、核数精确锁定修正管线 —— 诊断有效，修正解未采纳

**动机**：4 奇点交付解渲染出 5 个暗核（实验 4 个）。诊断发现三层根因：

1. **LG 模的各向异性 `(sx,sy)` 是伪物理**——`LG(p,0)` 施加 `sx≠sy` 后不再是 LG 模，
   圆对称节线被拉成椭圆，在中央撕出新的暗点。这与此前已确认的
   "LG 旋转是伪影"完全同构，但 `sx/sy` 当时漏做了同样的限制；
2. **核数容差成了漏洞**——原判据 `|Δ核数| ≤ 1`，5 vs 4 被放过；
3. **"提升"的真实来源**——LG 各向异性冻结后 4 奇点核数恢复 4vs4，
   但 `C_s02` 从 0.9163 掉到 0.8872，说明 v3 那 0.028 的提升**主要来自伪物理**。

| 脚本 | 作用 |
|---|---|
| `stage16_v4_terminal.py` | 终检 v4 修正管线（LG 排除各向异性/旋转 + 核数精确锁定，八图重跑） |
| `stage17_4sing_corelock.py` | 4 奇点定向搜索（LG 冻结 + 核数精确 = 4），30 候选中选出 `C_s02 0.8964` 解 |
| `stage17b_4sing_compare.py` | 四方案核数对比图（实验 / Sep26 / v3 / v4 / v17） |

**重要结论（已并入主线）**：

- ✅ **管线漏洞已修复**：`sx/sy` 与旋转一律 **HG-only**（LG 冻结）——
  该约束已固化进 `morph_search_lib` 的 `render_dof`，是**有效的方法改进**；
- ⚠️ **修正解整体未采纳**，交付仍维持 v3（用户决议）；
- ⚠️ **6 / 9 / 10 奇点在精确核数约束下无解** —— 其"核数差 1"不是参数问题，
  而是**模式基的表达极限**（此为有效结论，已写入 `METHOD.md` 已知限制）。

完整诊断：`reports/归档_八图分解/诊断_核数与自由度_2026-10-14.md`

## 三、运行说明

本目录的脚本按"工作记录"编写，内含原项目本机路径，
且通过 `from search_two_mode import ...` 等形式引用**上级目录**的已验证模块。

若确需运行（一般无需）：

```bash
# 让 Python 同时看到本目录与上级 src/
set PYTHONPATH=<repo>/src;<repo>/src/closed_routes   # Windows
export PYTHONPATH=<repo>/src:<repo>/src/closed_routes  # Linux/macOS

python src/closed_routes/stage14b_morph_audit_v2.py
```

这些脚本的输出通常写入原项目的归档目录，克隆后路径不存在，需自行调整。

# 相干光斑图模式分解（Coherent Beam Mode Decomposition）

> 从**单帧光强图**反推相干光场的模式成分：哪些模式、各占多少能量、相对相位是多少。

## 这份仓库解决什么问题

给定一张实验室拍到的激光光斑强度图 `I(x,y)`（**只有强度，相位测不到**），
本仓库提供一套可套用的流程，搜索出形成该光斑的模式叠加：

```
E(x, y) = Σ_k a_k · F_k(x, y) · exp(i·φ_k),        Σ_k a_k² = 1
```

**核心是这套扫描搜索方法，而不是某几张图的结果。**

## 本仓库提供什么（主要功能）

| 功能 | 入口 | 说明 |
|---|---|---|
| **端到端模式分解** | `pipeline.py` | 一条命令跑完：预处理 → 组合搜索 → 精修 → 结构验收，直接给出模式组合、能量占比与相对相位 |
| **分阶搜索** | `--stage two/three/four` | 从 8,515 组（两模）到 ≈1,171 万组（四模），由粗到细逐步升级 |
| **合成图自检** | `make_demo_image.py` | 造一张**已知答案**的理论光斑图，用于验证环境与精度（零外部数据） |
| **暗核结构验收** | `src/structural_check.py` | 独立于相关系数的判据：比对模型与实验的相位奇点数量与位置 |
| **指标标定** | `src/calibrate_metrics.py` | `C_s02` 等多尺度相关系数的计算与口径统一 |
| **精修内核** | `src/refine_all_new_method.py` | OLS 闭式上界 + 解析流形投影 + 多起点坐标下降 |
| **方法与踩坑指南** | `GUIDE.md` / `METHOD.md` | 判据推导、自由度审查、失败案例与移植到其他系统的建议 |

### 1.2 换成你自己的光斑图

```bash
# 灰度图：--cmap none ；伪彩图（如彩虹配色）：用对应配色名
python pipeline.py --image your_beam.png --img_dir ./data \
    --stage two --cmap none --expect-cores 4 --out_dir ./run1

# 两模不够 → 三模（全空间 366,145 组合）
python pipeline.py --image your_beam.png --img_dir ./data \
    --stage three --cmap none --expect-cores 4 --out_dir ./run1

# 更高阶 → 四模（guided：从三模结果扩展）
python pipeline.py --image your_beam.png --img_dir ./data \
    --stage four --cmap none --expect-cores 10 --out_dir ./run1
```

`--expect-cores` 是**你声明的暗核个数**——自己数图上的暗点填进去。
填错会把本该 PASS 的解判成失配。不确定时先不填，流程会自行统计实验图的暗核数。

流程会依次完成 **预处理 → 组合搜索 → 精修 → 结构化验收**，并输出：

| 输出 | 内容 |
|---|---|
| 模式组合 | 如 `HG(0,3) + HG(3,1)` |
| 能量/相位 | 各模式能量占比、相对相位（rad） |
| `C_s02` | 多尺度相关系数（主排序指标） |
| 暗核结构判定 | 模型 vs 实验的暗核数量与位置偏差 |

**完整套用指南见 [`GUIDE.md`](GUIDE.md)**（含判据、踩坑清单、移植到其他系统的建议）。

## 二、方法骨架：四层漏斗

这是一个**病态逆问题**：相位缺失、多组模式可产生相似光强（多模态简并）、
组合数随模式数爆炸（131 个模式，`C(131,4) ≈ 1,171 万`）。
因此采用"由粗到细"的漏斗式搜索，而非单点回归：

| 层 | 做什么 | 削减手段 |
|---|---|---|
| **L1 粗扫** | 降采样图上批量渲染全部组合 | GPU 向量化 + 降采样 |
| **L2 精筛** | 粗扫 top-K 在全分辨率复算 | 只算 top-200 |
| **L3 精修** | 优化振幅/相位/几何自由度 | OLS 闭式上界 + 坐标下降 + 多起点 |
| **L4 验收** | 结构与指标双重判定 | 暗核匹配（独立于相关系数） |

**关键工程点：解析化。** 两模/三模场景下光强可写成自项与互项的闭式组合：

```
I = Σ_k a_k²·B_k  +  2·Σ_{i<j} a_i·a_j·[cos φ_ij·C_ij − sin φ_ij·S_ij]
```

`B_k`、`(C_ij, S_ij)` 与参数无关，可预先算好；此后每换一组参数只是线性组合——
"渲染—评估"循环因此降为代数运算，千万级组合的普查才变得可行。

**模式基**：HG（`m+n ≤ 10`，66 个）+ LG（`2p+|l| ≤ 10`，65 个），合计 131 个模式。
组合规模：两模 8,515 → 三模 366,145 → 四模 ≈1,171 万 →
五模 2.98 亿（不可行，改用深度引导约 240 万组）。

**下标约定**：`HG(m,n)` 的 `m` 为**水平 x** 方向阶数、`n` 为**竖直 y** 方向阶数
（标准光学约定，Siegman / MATLAB 惯例），光斑为 `(m+1)` 列 × `(n+1)` 行；
`LG(p,l)` 的方位角 `θ = atan2(y, x)`。

**单一基族原则**：一个分解结果只用一种基族——要么全 HG，要么全 LG，不做混合。
两模阶段只开放 HG（快速侦察），三模及以上使用 HG+LG 联合基，
但交付解经纯基全空间复核确认。

## 三、判据：怎么知道解对了

**三个数决定是否收敛**（`pipeline.py` 会自动算并打印）：

| 指标 | 含义 | 期望 |
|---|---|---|
| `C_s02` | `[PCC(σ=0)+PCC(σ=2)]/2`，兼顾细节与低频 | 越高越好，0.85+ 通常可用 |
| 暗核数 | 模型 vs 实验 | **应相等** |
| `mean_nn_px` | 暗核位置平均偏差 | < 12 px |

### ⚠️ 最重要的经验：高相关 ≠ 正确

本项目 4 奇点早期曾出现 `C_s02 = 0.9163` 但**中央暗区占比 34%**（实验仅 6%）的解——
分数很高，人眼一看就不像。**全体像素相关系数对低频形态差异不敏感。**
（该图最终由纯 HG 全空间重搜解决：`C_s02 = 0.9514`、暗点 4/4 精确，见第四节。）

因此本项目的验收体系里，**暗核结构是独立判据**：用同一套检测器在实验图与
模型图上分别提取相位奇点，比对数量与位置。多次出现"`C_s02` 更高但核错位"
的候选被此判据正确排除。

**反面教训**：我们曾尝试用"形态指标"（中央暗区比、轮廓半径谱）作守门员，
结果**证伪**——指标判 PASS 的解视觉上反而更差。完整记录见
`reports/归档_八图分解/形态修复_2026-10-14/负结果记录_不采纳.md`。

> **记号约定（标准光学约定）**：`HG(m,n)` 中 `m` 为**水平 x** 方向的阶数、`n` 为

> 不出现 HG/LG 混合。八图中七张为纯 HG 解，5 奇点为纯 LG 解。
> 早期版本的混合基解（4 奇点 `C_s02 = 0.9163`、10 奇点 `C_s02 = 0.9013`）
> 已在纯基全空间重搜后被替代：4 奇点升至 0.9514 且暗点 4/4 精确，
> 10 奇点改为五模纯 HG 解 0.9285、暗点 10/10 精确。纯 LG 轨道未找到结构通过解。

逐图判定详见 `reports/八图最终交付_标准记号_2026-10-16/`（每图一份报告，含 `C_s02`、
暗核数与位置偏差）；完整过程与数值见 `reports/10.16汇报/`。

### 4.1 这些真实数据暴露出的方法边界

**① 组合层面的失配：高相关 ≠ 结构正确**
早期 4 奇点的混合基解含 35% 能量的高阶模式，其自带中央方形零点结构，
导致中央暗区 34%（实验 6%）。根因是**组合层面的失配**，而非参数没调好。
该图后来在纯 HG 全空间重搜中找到暗点 4/4 精确、`C_s02 = 0.9514` 的解——
说明当时是候选组合未被覆盖，而不是基的表达极限。
诊断见 `reports/归档_八图分解/诊断_4奇点轮廓分析报告.md`。

**② 部分图的"核数差 1"是模式基的表达极限**
用精确核数约束（`Δ核数 == 0`）重跑后，**6 / 9 奇点无解**——
说明这些图的核数差不是参数问题，而是基的表达极限。已如实记录。
（10 奇点同属此列，后经纯基五模全空间搜索解决，暗点 10/10 精确。）

**③ 一个通用陷阱：伪物理自由度会刷出假分数**
- **LG 模的旋转**等价于相位平移，开放它会让优化器通过插值伪影骗取增益；
- **LG 模的各向异性 `sx≠sy`** 破坏 LG 模定义（圆形节线被拉成椭圆），
  在中央撕出额外暗点——早期 4 奇点解因此从 4 核变 5 核。

修正后该解 `C_s02` 从 0.9163 掉至 0.8872，说明那 0.028 的提升**主要来自伪物理**。
**教训**：每引入一个自由度，先问"它在物理上是否合法"。
该约束现已固化为 `sx/sy` 与旋转一律 HG-only。

> **为什么保留这些未解决的记录**：本项目的每个方向都以"判决"收束——
> 要么通过验收，要么被对照实验证伪并如实披露。已知极限与负结果同样是结论。
> 详细过程见 `reports/归档_八图分解/诊断_核数与自由度_2026-10-14.md`。

## 五、技术路线说明（公开范围）

本项目历史上探索过两条技术路线：

| 路线 | 方法 | 本仓库 |
|---|---|---|
| ① 神经网络线 | ResNet34 骨干，单帧光强图 → 多阶 HG 模式权重端到端回归（91 维，L2 能量约束）；8 万张仿真数据，含锁定相位 / SHG 双通道 / hg-only 三阶段域差距对照实验 | **不发布**（2026-10-09 已决策放弃该路线，代码、数据、权重与实验报告均不在此仓库） |
| ② 搜索/精修线 | 物理模型 + 组合搜索 + 逐级精修 + 结构化验收 | **本仓库主体** |

**为什么只公开第二条线**：

1. 路线① 已被放弃——它在真实实验图上遇到"仿真到真实"的域差距瓶颈，
   最终未作为交付方案；
2. 其数据集（数十 GB 仿真数据）与训练权重也不适合公开发布，
   且可能涉及课题组未发表内容。

因此本仓库**只包含经八图验证有效的搜索/精修方法**。
路线① 的存在与放弃原因在 `METHOD.md` 的"已知限制"中有简要说明，

## 六、目录结构

```
.
├── README.md                  本文件：方法总览 + 演示 + 真实数据验证 + 已知边界
├── GUIDE.md                   套用指南：步骤 / 判据 / 踩坑 / 移植建议

├── requirements.txt           依赖清单
├── LICENSE                    使用许可与声明
├── 文件清单.md                 全仓库文件逐项标注
├── src/
│   ├── search_*.py            ★ 组合搜索引擎（两/三/四模，已参数化）
│   ├── refine_all_new_method.py  ★ 精修内核（可作为库调用）
│   ├── structural_check.py    ★ 暗核结构验收（可作为库调用）
│   ├── calibrate_metrics.py   ★ 指标计算与标定
│   ├── hg_generator.py 等      物理内核（模式基）
│   ├── stage*.py              本项目各轮工作的脚本（工作记录）
│   ├── probe*.py diag_*.py    物理探针与诊断脚本（工作记录）
│   └── closed_routes/         ⚠ 已关闭路线的脚本（证伪/未采纳，仅供追溯）
├── reports/
│   ├── 八图最终交付_标准记号_2026-10-16/ 真实数据验证的最终结果（标准记号版）
│   ├── 八图最终交付_2026-10-14/ 同批结果的早期版本
│   ├── 10.16汇报/              记号对齐与单一基族统一的过程与数值
│   ├── 归档_八图分解/           全流程归档（含负结果与诊断）
│   └── *.md                   搜索线的阶段报告
└── (无图像目录：本仓库不发布任何实验图像)
```

> **关于三类脚本的区分（重要）**
>
> - **★ 标记 = 可复用的方法实现**：带 `--image` / `--img_dir` 等参数，
>   不依赖本项目路径，可直接用于你自己的光斑图（`pipeline.py` 会编排它们）。
> - **`stage*.py` / `probe*.py` / `diag_*.py` = 本项目工作记录**：
>   为具体某张验证图、某次实验而写，脚本内写定了本项目的图片名与参数。
>   它们从 `images/` 子目录读图（可用环境变量 `SPOT_IMG_DIR` 覆盖指向，
>   详见 `GUIDE.md` 步骤 0）。保留它们是为了让 `reports/` 中每一份报告
>   都可追溯、可复核——这是完整的科研审计轨迹，而不是通用入口。
> - **`closed_routes/` = 已关闭路线**：被证伪或未采纳的尝试
>   （形态先验搜索、核数锁定修正管线）。**不要从这里开始**；
>   它们存在的意义是让"为什么这条路走不通"可被验证，
>   并保留其中有复用价值的工具（如 `morph_search_lib.render_dof`）。
>   详见 `src/closed_routes/README.md`。

## 八、安装方法

```bash
git clone <本仓库地址>
cd <仓库目录>

# 建议使用虚拟环境
python -m venv .venv
# Windows:  .venv\Scripts\activate
# Linux/macOS:  source .venv/bin/activate

pip install -r requirements.txt
```

`requirements.txt` 内容：

```
torch>=2.0
numpy>=1.24
scipy>=1.10
pandas>=2.0
matplotlib>=3.7
Pillow>=10.0
```

**环境要求**：

| 项 | 要求 |
|---|---|
| Python | ≥ 3.9（代码用到海象运算符与内置泛型标注）；开发验证环境为 3.14 |
| PyTorch | ≥ 2.0，建议装与本机 CUDA 匹配的版本；**无 GPU 也能跑**（自动回落 CPU，仅大组合搜索变慢） |
| 显存 | 四模搜索建议 ≥ 4 GB；两模/三模 CPU 亦可 |

**验证安装**（零外部数据，几十秒出结果）：

```bash
python make_demo_image.py --out ./data/demo.png --truth ./data/demo_truth.json
```

能打印出"检测到暗核：7 个"即环境正常。见 1.1 节的完整演示。

`pipeline.py` 是套用入口；`src/` 下的脚本可按阶段单独调用，各自对应 `reports/` 中的报告。

**本仓库包含**：方法代码、结论文档、结果数据（JSON/CSV/报告）。
**不包含**：任何实验图像（原始 PNG 与含实验图的结果对比图均不发布）、
仿真数据集、模型权重。
